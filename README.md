# Portfolio

スクロールしない SPA 型のポートフォリオサイト。

- **SPA** — 4つのセクションを、ページ遷移なしで切り替える
- **スクロールなし** — 常に `100dvh` に収まり、ページ全体はスクロールしない
- **ライト / ダーク** — OS 設定にそのまま追従する（切り替え UI は持たない）

## セットアップ

Node は **22.12 以上**（`.nvmrc` を置いてあるので `nvm use` で合う）。

```bash
npm install
npm run dev      # 開発サーバ
npm run build    # 型チェック + 本番ビルド
npm run preview  # ビルド結果の確認
```

## 品質チェック

```bash
npm run check         # 整形 → Lint → 文言 → 型チェック＋ビルド（CI と同じ内容）
npm run format        # Prettier で整形
npm run format:check  # 整形されているかだけ確認
npm run lint          # Oxlint
npm run check:copy    # 文言の語尾がそろっているか
npm run og            # OGP 画像を作り直す（playwright が必要）
```

`npm run check` が通れば CI も通る。push 前にこれだけ流せばよい。

## 公開

**main に push すると自動でビルドされ、GitHub Pages に公開される。**
手動のビルドやアップロードは不要。

初回だけ、リポジトリ設定でスイッチを入れる必要がある:

1. GitHub の **Settings → Pages** を開く
2. **Source** を `GitHub Actions` にする
3. main に push（または Actions タブから `Deploy` を手動実行）

公開先は `https://<ユーザー名>.github.io/<リポジトリ名>/`。
サブパス配信になるため、ビルド時に `BASE_PATH` を渡して `vite.config.ts` の `base` を合わせている
（`.github/workflows/deploy.yml` が自動で設定する）。

独自ドメインや `<ユーザー名>.github.io` リポジトリで公開する場合は、
`deploy.yml` の `BASE_PATH` を `/` に変更する。

## 自動チェック

| 仕組み       | 実行タイミング                   | 内容                                     |
| ------------ | -------------------------------- | ---------------------------------------- |
| `CI`         | main 以外への push、Pull Request | 整形 / Lint / 文言 / 型チェック / ビルド |
| `Deploy`     | main への push、手動実行         | ビルドして GitHub Pages に公開           |
| `Dependabot` | 毎週月曜（Actions は毎月）       | 依存の更新 PR をまとめて作成             |

Dependabot の PR は CI が通っていればマージするだけでよい。

## 内容の差し替え

表示される内容はすべて **[`src/data/portfolio.ts`](src/data/portfolio.ts)** に集約している。
名前・経歴・作品・スキル・SNS リンクを書き換えれば、他のファイルに触れずに自分の内容になる。

`skillGroups` は About の下段に出る。`experience`（例: `'3年以上'`）を入れると
名称の右に経験年数が並ぶ。`works` は1画面に収まる **6件まで**。
7件目を足すときは代わりに1件外すこと。

**履歴書に載っていても、公開サイトに出してはいけない情報がある。**
生年月日・性別・電話番号・年収・転職希望条件などは `portfolio.ts` に書かないこと。

あわせて差し替えるもの:

| 対象                         | 場所                                                       |
| ---------------------------- | ---------------------------------------------------------- |
| ページタイトル / description | `index.html`                                               |
| OGP の文言 / 公開 URL        | `index.html` の `og:*` と JSON-LD                          |
| OGP 画像                     | `scripts/og-image.html` を直して `npm run og`              |
| favicon                      | `public/favicon.svg`（モノグラム）                         |
| ポートレート写真             | `src/sections/About.tsx` に `<img>` を足し、列を1つ増やす  |
| 作品のリンク先               | `src/data/portfolio.ts` の `works[].repo` / `works[].demo` |
| 問い合わせの送信先           | `src/sections/Contact.tsx`（現在は `mailto:` リンクのみ）  |
| 配色                         | `src/styles/tokens.css`                                    |

## 構成

```
src/
├─ data/portfolio.ts        表示内容（ここだけ編集すればよい）
├─ hooks/
│  ├─ useSectionRouter.ts   現在のセクション・URL hash 同期・キーボード操作・送りの向き
│  ├─ useScrollable.ts      はみ出しの検知（スクロール領域に tabindex を付ける判断）
│  └─ useCountUp.ts         実績値の数え上げ
├─ components/
│  ├─ Sidebar.tsx           左の固定ナビ（項目はリンク）
│  ├─ Panel.tsx             各セクション共通の枠（見出し + 本体）
│  └─ Icon.tsx              インライン SVG アイコン
├─ sections/                Home / About（経歴 + 技術）/ Works / Contact
└─ styles/
   ├─ tokens.css            配色・文字サイズ・余白・モーションのトークン
   └─ global.css            リセットと基本スタイル
```

## 操作

| 操作                  | 動作                       |
| --------------------- | -------------------------- |
| 左ナビのクリック      | 該当セクションへ           |
| 左ナビを中クリック    | 新しいタブで開く           |
| `←` `→`               | 前後のセクションへ         |
| `↑` `↓` `PageUp/Down` | パネル内の内容をスクロール |
| ブラウザの戻る / 進む | セクション履歴をたどる     |
| URL の `#works` など  | 直接そのセクションを開く   |

ナビと Home の行き先は**ボタンではなくリンク**（`<a href="#works">`）にしている。
やっていることは hash を書き換えることなので、リンクにすれば新しいタブで開く・
URL をコピーする・リンクとして読み上げる、がそのまま手に入る。
表示の切り替えは `hashchange` 側が受け持つので、遷移用の関数は配っていない。

セクション送りは**横方向のキーだけ**に割り当てている。縦方向まで奪うと、
パネル内に収まりきらなかった内容をキーボードでスクロールできなくなるため。
入力欄にフォーカスがあるときは、矢印キーをセクション送りに使わない。

## 置いていないもの

意図的に持たせていない機能がある。足す前に、本当に要るか確認すること。

| 機能               | 理由                                                              |
| ------------------ | ----------------------------------------------------------------- |
| Home の実績・所属  | すべて About と Works にある。同じことを2回言わせない             |
| 問い合わせフォーム | サーバがないので `mailto:` を組み立てるだけになり、二度手間になる |
| テーマ切替 UI      | OS 設定に追従すれば足りる。`localStorage` を触らずに済む          |
| Works のページ送り | 1画面に収まる6件を厳選する運用にしている                          |
| パネルのフッタ     | 現在地とページ送りは左ナビとキーボードが担う                      |

## スクロールさせないための設計

1. `html, body, #root` に `height: 100%` と `overflow: hidden`、ルートは `100dvh`。
2. Grid / Flex の子には `min-height: 0` `min-width: 0` を付ける
   （既定の `min-content` が、はみ出しの主な原因になる）。
3. 各パネルは「見出し（固定）+ 本体（`flex: 1`）」の2層。
   高さが変わっても本体だけが伸縮する。
4. Works は **1画面6件** に固定する。増やすなら1件外す。
5. 余白と文字サイズは `clamp()` でビューポートに連動させる。
6. パネル本体には `overflow-y: auto` を安全網として置く。
   どう詰めても収まらない画面で、本文が見出しに重なるのを防ぐためのもので、
   収まっている限りスクロールバーは出ない。**ページ全体は常にスクロールしない。**
7. 中央揃えには `safe center` を使う。
   素の `center` は、内容がはみ出したときに先頭をスクロール範囲の外へ押し出してしまう。

## 動き

動きは「今どこにいるか」を伝えるためだけに入れている。装飾のための動きは足さないこと。

| 場所             | 動き                                          | 何のためか                                           |
| ---------------- | --------------------------------------------- | ---------------------------------------------------- |
| パネルの切り替え | 進むと右から、戻ると左から入る（±28px）       | 4画面が横一列に並んでいると感じさせ、前後関係を示す  |
| パネルの中身     | 上から順に 40ms ずつ遅れて現れる              | 目線の入口を作る。読む順序が視覚的に決まる           |
| Works の実績値   | 表示された瞬間に 0 から数え上げ、バーが伸びる | 数字に目を留めさせる                                 |
| 左ナビの標識     | 選択中の位置へ滑る                            | 背景色の瞬間入れ替えだと「消えて現れる」に見えるため |
| 作品カード       | ホバーで下線が左から伸び、背景が少し浮く      | 触れる対象であることを示す。影で浮かせると重く見える |

決め事:

- **送りの向き**は `useSectionRouter` が `'fwd' | 'back'` で持ち、`<main data-way>` から CSS に渡す。
  リンクとブラウザの戻る/進むでは、hash の位置関係から向きを決める。
  キーボード送り（`shift`）だけは先に向きを決めてから hash を書き換えるので、
  位置が変わっていなければ `hashchange` 側では何もしない（決めた向きを潰さないため）。
- **順送りの遅延**は CSS だけで組む（`global.css` の `.stagger`）。JS のタイマーは持たない。
  animation は**表示中のパネルにだけ**与える。離れると animation ごと外れ、戻ると新しく始まるので、
  訪れるたびに再生される。`animation-play-state: paused` で待たせる作りにしないこと
  （一度終わったアニメーションは再開しても何も起きず、初回しか動かなくなる）。
  同じ理由で、実績バーの `metric-grow` も `[data-active='true']` の下でだけ与えている。
  常時与えると、隠れているあいだに伸び終わってしまい、数字だけが動いて見える。
- `animation` の一括指定は `animation-delay` を 0 に戻す。遅延を別に指定しているので、
  表示中パネルの指定は個別プロパティで書くこと。
- 遅らせるのは**先頭6要素まで**。それ以上は最後の遅延のままにする（待たされている感じになるため）。
- **数え上げは1画面に1つだけ**。増やすと安っぽくなる。`portfolio.ts` の `metric` は業務カードにしか付けていない。
- `prefers-reduced-motion: reduce` のときは、遷移も順送りも止め、数字は最初から最終値を出す。
  時間だけでなく**遅延も 0 にする**。時間を 0 にしても遅延（最大 320ms）が残ると、
  中身が順番に現れるという動きそのものは見えたままになる。
- 数え上げ中の数字は `aria-hidden` にし、読み上げ用に最終値を別途置いている。
  途中の値を読み上げさせないため。
- **ホバーの流儀は2つ。混ぜないこと。** 押すもの（ボタン・ピル・アイコン）は
  `translateY(-2px)` で浮かせる。面（作品カード）は下線が左から伸びる。
  カードを影で浮かせると、静かな配色のなかで一気に重く見える。

## レスポンシブ

| 幅                  | 変化                                       |
| ------------------- | ------------------------------------------ |
| 1200px 未満         | Works が 3×2 → 2×3                         |
| 900px 未満          | 左サイドナビ → 上部バー、2カラム → 1カラム |
| 560px 未満          | Works が 1カラム                           |
| 高さ 820/680px 未満 | About の余白と行間を2段階で詰める          |

900px 未満では左ナビが上部バーになり、項目が横に並ぶ。
このとき滑る標識は隠し、選択中の項目は背景色で示す（横並びだと標識の移動距離が長く、
かえって落ち着かないため）。

**Email と GitHub のリンクは隠さない** — ここを落とすと連絡手段が消えるため。

### 作品カードの説明文が読めるか

`summary` は行数で打ち切っている（幅 900px 以上で5行、未満で4行）。
打ち切りは最後の逃げ道であって、既定の状態にしてはいけない。**書いた文章は読まれること。**

- 560px 未満（1カラム）では `.summary` を `flex: none` にして縮ませない。
  既定のままだとカードが下限の 150px に張りつき、4行の指定に対して1行しか出ない。
  実績値を持つカードではその1行も消えて、説明が丸ごと読めなくなる
- 実績値（`metric`）を持つカードは1行ぶん背が高い。**そのカードの `summary` は短く書く**
- 1920/1440/1280/1024/768/390 の各幅で、6件とも全文が出ることを確認している。
  縦 568px / 720px の低いウィンドウでは 2カラムのカードが詰まり、
  一部が打ち切られる。ここはスクロールを出さないほうを選んでいる

パネル内部のスクロールが出るのは以下（ページ全体は常にスクロールしない）。
スクロールが要るときだけ、本体に `tabindex="0"` が付いてキーボードで掴めるようになる。

| 画面          | 内部スクロールが出るセクション |
| ------------- | ------------------------------ |
| 1024×768 以上 | なし                           |
| 768×1024      | About                          |
| 390×844 以下  | About / Works                  |

本文量が増えると、縦の短い画面では収まらなくなる。文章を削るより
スクロールに逃がすほうが情報を落とさずに済むと判断している。

## パネルの縦位置

4つのパネルはすべて**内容を縦中央に置く**。上詰めにすると、内容の少ないパネルだけ
下に大きな空洞ができ、セクションを送るたびに内容が上下に飛んで見える。

Works は行の高さを中身なりにしたまま（引き伸ばすとカード内に空白ができる）、
2行のかたまり自体を `align-content: safe center` で中央へ置いている。

上下の余白の差は、1920×1080 / 1440×900 / 1280×800 のいずれでも **8px 以内**。

## 文言とデザインの決め事

**文言**（`src/data/portfolio.ts` の冒頭にも書いてある）

層ごとに語尾の型を決めてある。**層をまたいで混ぜないこと。**
体言止めとです・ますが同じ画面に並ぶと、そこだけ書き手が変わったように見える。

| 層     | 対象                                   | 型                             | 例                             |
| ------ | -------------------------------------- | ------------------------------ | ------------------------------ |
| 見出し | `headline` / `contact.title`           | 言い切り（動詞で終える）       | 「仕組みで変える。」           |
| 本文   | `lead` / `bio` / `contact.lead`        | です・ます                     | 「取り組んでいます。」         |
| カード | `works` の `summary`                   | 体言止め。→ である。の2文      | 「常駐アプリ。配布している。」 |
| ラベル | `career` / `skillGroups` / `role` など | 名詞のまま（「。」を付けない） | 「個人開発」                   |

- 英字語と日本語のあいだには半角スペースを1つ（「生成AI」など定着した語は例外）。
  「14画面」「約200名」のような数字＋助数詞は空けない
- セクション名・ラベル（`Languages` など）は英語

この4層は `npm run check`（CI でも実行）で機械的に検査している。
崩すと落ちるので、型を変えるときは [`scripts/check-copy.mjs`](scripts/check-copy.mjs) も直すこと。

**デザイン**（`src/styles/tokens.css`）

配色・文字サイズ・余白・モーションの決定は**すべて `tokens.css` の中で行う**。
各 CSS ファイルに生の値を書かないこと。値が散ると
「5px と 6px の違いに意味があるのか」が誰にも分からなくなる。

| 種類       | 段数 | トークン                                                                     |
| ---------- | ---- | ---------------------------------------------------------------------------- |
| 本文の字   | 6    | `--fs-label` 10px 〜 `--fs-lg` 17px                                          |
| 見出しの字 | 7    | `--fs-lead` / `--fs-card-title` / `--fs-display` など（clamp）               |
| 余白       | 7    | `--sp-1` 2px / `--sp-2` 4px / 8 / 12 / 16 / 24 / `--sp-7` 32px               |
| 動きの時間 | 4    | `--dur-fast` 180ms / `--dur` 320ms / `--dur-rise` 420ms / `--dur-slow` 900ms |
| 文字色     | 3    | `--ink` / `--ink-mid` / `--ink-weak`                                         |
| 角丸       | 3    | `--radius` / `--radius-sm` / `999px`（丸ピル）                               |

- **中間の値を足さないこと。** 300ms と 320ms、5px と 6px のような差は
  誰にも見分けられず、揃っていない印象になるだけで情報の序列は増えない。
  近い値が要ると思ったら、既にある段へ寄せる
- **本文の字と見出しの字は混ぜない。** 見出しは画面幅に連動させるので `clamp` で持つ
- 画面に連動させたい余白（`--gutter` など）は `clamp` で別に持つ。余白の段には載せない
- 区切り線つきの行の上下余白は `--row-pad` 12px、行数が多い一覧は `--row-pad-tight` 8px

## アクセシビリティ

- ページの `h1` は `App.tsx` が持ち、各パネルが `h2`、カードが `h3`。
  見出しレベルが飛ばないようにしてある
- 非表示のパネルは `inert` にして、Tab とスクリーンリーダーから外す
- セクションが変わったことは `role="status"` の領域で読み上げる
- 文字色は `--ink` / `--ink-mid` / `--ink-weak` の3段。
  最も薄い `--ink-weak` でもライト 4.80:1 / ダーク 5.73:1 で、WCAG AA を満たす
- `prefers-reduced-motion: reduce` でアニメーションを止める。
  順送りの表示も、実績値の数え上げも、この設定では最初から最終状態になる
  （動きを止めた結果、内容が出てこないということがないようにしてある）

## ワイヤーフレーム

設計時のワイヤーフレームと意図は [`docs/wireframe/`](docs/wireframe/) に残してある。
